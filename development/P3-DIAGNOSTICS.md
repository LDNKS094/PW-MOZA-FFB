## 怎么测试

在项目根目录打开终端，先运行已编译的诊断桥接：

```powershell
dotnet src/bridge/bin/Release/net8.0/PWBridge.dll
```

若从干净代码重新构建：

```powershell
dotnet build src/bridge/PWBridge.csproj -c Release
```

保持桥接运行，从 Steam 启动游戏：

1. 平飞约 20 秒，然后分别改变油门、抬头/低头、左右滚转。
2. 暂停约 5 秒，再恢复；桥接可能显示 timeout 并等待自动重连，这是当前预期行为。
3. 返回菜单，正常退出游戏；然后在桥接窗口按 Ctrl+C 停止录制。
4. 告知完成，检查实际帧率、速度/G 值噪声、重定位、暂停和会话复位。

桥接启动时打印本轮目录，原始管道数据保存在：

```text
development/artifacts/p3-<UTC时间>/capture.txt
```

每轮使用新文件，不覆盖旧录制。退出/断线会写入 `none` 分界。没有后台桥接进程自动留驻，需自行启动；开始时游戏不运行也可以等待。不要同时运行两份诊断桥接。

## 采样与协议

- 游戏线程每个飞行 tick 读取数据，以引擎真实时间限制为最高约 60 Hz；实际频率取决于 tick 与调度。
- 只接受已验证类的本地玩家，世界位置先加原点、再从 cm 转成 m；姿态保留度，游戏/真实时间保留秒，前向速度从 cm/s 转 m/s。HUD 的 km/h/节不参与协议。
- 仅缓存一个最新字符串，`LoopAsync(16)` 负责打开/写入 `\\.\pipe\PWTelemetry`。所有 UObject 读取仍在游戏线程。
- 不堆积历史帧，不重复发送相同序号。切出飞行、读取失败、健康值无效/归零或销毁时设置 `none`；读到暂停也发送 `none`。
- 若暂停导致 tick 停止，靠桥接 500 ms 新鲜度超时清空诊断状态并关闭连接；恢复时自动重连。重复序号不会延长新鲜度。
- 当前没有依赖未知语义的 `a_AfterburnerFloat` 或模拟按钮事件。

单行 v1 示例：

```text
v=1;s=10;q=123;t=90.123456;rt=100.123456;x=16640.1;y=-1040.2;z=780.01;p=0;yaw=-163.0647;r=0;spd=231.48168;hp=100;dead=0;
```

字段：版本、会话、序号、游戏时间、真实时间、绝对世界位置 m、俯仰/航向/横滚度、游戏前向速度 m/s、健康值、销毁标记。

桥接检查版本、必需字段、重复字段、有限值、ID 和基本范围；拒绝超长/截断行。单行上限 2048 字符，只允许同一用户连接命名管道。

## 速度重建与运动转换

- 用游戏前向速度确定大小、绝对世界位置差确定运动方向，双精度重建速度估计。不能直接用高频位移/dt 确定大小（已发现 tick 相位噪声），也不用全零的 `GetVelocity()`。非零速度但位置重复时输出失效状态，保留历史等待新位置，超出时间门槛则复位。
- 启动/换会话前两帧预热，不据此生成动态运动值。
- dt 小于 0.1 ms、游戏或真实间隔超过 250 ms、两者差异超过 100 ms时重置历史。
- 重建速度按当前游戏时间打点，求导后投影到机体坐标，减去重力得到计算的比力 G。姿态差先跨 ±180° 修正，再转为角速度。方向来自上一段位移，存在采样延迟，派生攻角/侧滑并非真实气流测量。
- 先拒绝明显位置跳变和超过 50 G 的差分异常，再滤波和限幅。位置跳变门槛为原始位移/dt 大于 `2 × 相邻最大前向速度 + 50 m/s`。
- 本轮 G 范围沿用参考实现（前/侧向 ±4 G，法向 −4～12 G），角速度限制 ±20 rad/s。这些只是诊断阶段的保守限制，**不是经过 PW/硬件验证的校准**，可能屏蔽极端机动。
- 生成 DCS 格式的已知运动字段，仅用于日志/离线验证；`tas` / `ias` 与参考一致使用游戏速度代理，不声称是真实空速。未知转速、武器、天气、起落架等不伪造，不写固定弹药/高度或猜测加力。
- 这里的 safe frame 是诊断状态输出，不代表已经确认 Cockpit 或底座能安全释放力。

核心投影/滤波及字段映射改编自 AC7 项目，遵守根目录 GPL-3.0 `LICENSE`；未复制 AC7 Hook 地址或设备输出逻辑。

## 离线自检与回放

```powershell
dotnet src/bridge/bin/Release/net8.0/PWBridge.dll --self-test
npx --yes --package=fengari-node-cli fengari development/test-probe.lua
dotnet src/bridge/bin/Release/net8.0/PWBridge.dll --replay development/artifacts/p3-<时间>/capture.txt
```

已通过：

- C#：字段校验、SI 速度、前两帧预热、会话/乱序/时钟/暂停/长间隔复位、瞬移/加速度尖峰、角度跨界、恒定加速、侧倾重力投影、非英文区域格式、真实命名管道读写及取消、超长/截断行。
- Lua：对象/会话门控、原点/SI 转换、高频采集与低频日志、非有限值和死亡失效、去重、异步写失败重连。
- 端到端合成测试：100 个帧产生 2 个预热和 98 个有效运动结果，额外重复帧被忽略，500 ms 失联复位，录制回放一致。
- 合成验证进程已停止，临时录制已清理；保留的是持续用于回归的自检代码，不是一次性探测脚本。

**未验证：** 死亡标记的准确生效时刻/原因、过场时效、所有姿态方向、Cockpit 字段需求/安全停止、底座响应。修订版已验证暂停恢复、重试换会话与返回菜单分段，但不是硬件校准。P4 可准备协议和限力方案，未确认条件前不得开启设备输出。

## 回退

游戏退出后，将本轮部署目录的 `previous-main.lua` 复制回 Win64 的 `Mods/PWProbe/Scripts/main.lua`，即可回到原点日志探针；先保留当轮 UE4SS.log 和 capture.txt。停止诊断桥接后它不会再工作，不需要修改存档或端口配置。
